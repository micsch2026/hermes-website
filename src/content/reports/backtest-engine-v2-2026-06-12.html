🎯 Kernbefunde → v3 Features

1️⃣
Pluggable Models → IFeeModel Interface. LEAN und Nautilus trennen Engine von Kostenmodell. v3 implementiert IFeeModel als ABC — Pepperstone als Default, erweiterbar für andere Broker.
2️⃣
Bootstrap CI → Statistische Validierung. Professionelle Systeme geben nicht nur Punktschätzungen aus. v3 berechnet 95%-Konfidenzintervalle (5000 Resamples) für WR, PF, Expectancy.
3️⃣
SQN → System-Qualitäts-Metrik. Van Tharp's System Quality Number bewertet nicht nur Profitabilität sondern Konsistenz. v3 ergänzt dies um Monte-Carlo-Permutation.
4️⃣
Event Bus → Loose Coupling. LEAN's Algorithm Framework nutzt Events für Modul-Kommunikation. v3 implementiert einen einfachen EventBus für Engine ↔ Analytics.
5️⃣
SQLite → Persistente Historie. Statt JSON-Files pro Run speichert v3 alle Runs, Trades, Equity-Curves und Walk-Forward-Splits in einer SQLite-DB — querybar, versioniert, platzsparend.

💰 4. Kostenmodell — Pluggable Interface

v2: CostModel (hardcoded)

class CostModel: def __init__(self, config: CostConfig): self.config = config def get_spread_pips(symbol, hour_utc) def calc_commission_eur(volume) def get_slippage_pips(symbol, atr, vol, hour) def calc_swap_eur(volume, direction, nights)

v3: IFeeModel (pluggable)

class IFeeModel(ABC): @abstractmethod def get_spread_pips(symbol, hour_utc): ... @abstractmethod def get_commission_eur(volume): ... @abstractmethod def get_slippage_pips(symbol, atr, vol, hour): ... @abstractmethod def get_swap_eur(volume, direction, nights): ... class PepperstoneRazorCostModel(IFeeModel): # Default implementation # Pair-specific swaps, Wed 3x, dynamic EURUSD

🚀 5. Neue Features in v3

📊 Bootstrap Confidence Intervals

5000 Resamples, 95% CI auf WR, PF, Expectancy. Zeigt ob Ergebnisse statistisch signifikant sind.

# Ergebnis-Beispiel: WR: 67.1% [61.2%, 72.8%] ✅ PF: 2.17 [1.82, 2.58] ✅ Exp: €4.25 [€3.10, €5.40] ✅

🎲 Monte Carlo Permutation

Shuffled Trade-Reihenfolge × 1000 Simulationen. Zeigt DD-Verteilung und Profit-Wahrscheinlichkeit.

# Ergebnis-Beispiel: Simulations: 1000 P(Profit): 94.2% MaxDD P95: 18.3% MaxDD P99: 24.1%

📈 SQN (System Quality Number)

Van Tharp's Metrik: Konsistenz der Returns. SQN > 2 = gut, > 3 = sehr gut, > 5 = hervorragend.

# Ergebnis-Beispiel: SQN: 3.87 (ROBUST) Mean R-Multiple: 0.42 R-StdDev: 0.31

🧪 Walk-Forward v3 (True Re-Optimization)

v2: Filtert nur OOS-Fenster aus Gesamt-Backtest (keine echte Validierung). v3: Re-optimiert Parameter pro Split via Grid-Search, dann OOS-Test.

class WalkForwardV3: def run(config, bot_id, n_splits=5, param_grid=...): # Für JEDES Split: # 1. Train auf Daten 1-N # 2. Grid-Search für optimale Params # 3. OOS-Test mit optimierten Params # 4. Decay Detection: degradieren Ergebnisse?

💾 SQLite Data Layer

v2: JSON-Files pro Run (scattered, nicht querybar). v3: SQLite-DB mit allen Runs, Trades, Equity, WF-Splits.

Tables: runs — Config + Summary pro Run trades — Einzeltrades mit Kosten-Aufschlüsselung equity_curve — Zeitreihe pro Run wf_splits — Walk-Forward Ergebnisse pro Split Location: /root/fx-bot/data/backtest_v3/history.db

🔌 Signal Registry

v2: Monolithisches signals.py. v3: Plugin-System mit Auto-Discovery.

@register class MeanReversionSignals(SignalBase): name = "mean_reversion" def generate(bars, config): ... @register class TrendSignals(SignalBase): name = "trend" def generate(bars, config): ... # Auto-dispatch via registry.get(name)

v2: Direkte Funktionsaufrufe (tight coupling). v3: Publish/Subscribe für Loose Coupling.

🎯 8. Design-Entscheidungen (begründet)

✅ Frozen Config

@dataclass(frozen=True) — wie v2. Verhindert Mutation während Backtest. Grund: LEAN und Backtrader nutzen ebenfalls immutable Config-Objekte.

✅ IFeeModel Interface

LEAN-Pattern: Abstract Interface für Kostenmodelle. Grund: Ermöglicht Broker-Switch ohne Engine-Änderung. Pepperstone als Default.

✅ Mark-to-Market Equity

v2 nutzte nur realized PnL. v3 berechnet Equity = realized + unrealized. Grund: NautilusTrader und LEAN nutzen MTM für korrekte DD-Berechnung.

✅ SQLite statt JSON-Files

v2: JSON pro Run (scattered). v3: SQLite-DB. Grund: Querybar (WHERE sqn > 3), platzsparend, ACID, kein File-Chaos.

✅ Signal Registry

Plugin-System mit Decorator-Registration. Grund: Backtrader nutzt Strategy-Klassen. Neue Strategien nur registrieren, nicht engine ändern.

✅ Event Bus

Publish/Subscribe statt direkte Aufrufe. Grund: LEAN's Algorithm Framework. Analytics-Module können unabhängig erweitert werden.
